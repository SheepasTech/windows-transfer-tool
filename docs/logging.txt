DEBUG LOGGING
=============

Debug logging is always on. It cannot be switched off, on the old PC or the new PC.

Where the logs are
------------------
  %TEMP%\WindowsTransferTool\logs
  (usually C:\Users\<you>\AppData\Local\Temp\WindowsTransferTool\logs)

What is written there
---------------------
  debug-source-<date>-<time>.log        full console transcript of an old-PC run
  debug-destination-<date>-<time>.log   full console transcript of a new-PC run
  robocopy-<date>-<time>.log            robocopy's own log (new PC)

The transcript is started by Start-DebugLog in Migrate-Windows.ps1 as soon as the
tool knows whether this is the old or the new PC. It is stopped when the tool ends,
including after an error. Every run makes a new file; old files are never overwritten.

Not in the temp folder
----------------------
  - With -Transport Drive on the old PC, the robocopy log is also written to
    WTT-Transfer\logs on the drive.
  - Registry backups and the installed-apps CSV on the new PC stay in
    %USERPROFILE%\Migration. They are reports, not debug logs.

Desktop shortcut
----------------
At the start of each run the tool looks for "Transfer logs.lnk" on the desktop.
  - If it exists, nothing happens.
  - If it is missing, the tool asks: Put a "Transfer logs" shortcut on the desktop? (Y/n)
    Enter creates it. n skips it (it asks again next run).
  - With -Yes, or when the tool is not interactive, it creates the shortcut without asking.
  - If the shortcut cannot be created, the tool prints a warning with the folder path.

The bootstrap (bootstrap.ps1) prints "Running: Migrate-Windows.ps1 -Mode ..." with the
exact parameters it passes to the tool. That line is part of the transcript.

Privacy: secrets are hashed in the saved log
--------------------------------------------
The old PC prints one-time sign-in details on screen for you to type on the new PC
(pairing code, FTPS/FTP password, SMB temporary-account password). The screen still shows
them in full. When the tool ends, it rewrites the saved debug log and replaces each of
those values with a short SHA-256 hash, for example:

  Pairing code:   [sha256:4981aa0a50d5]

So a log you keep or share does not hold a usable password. The hash lets you check that
two lines refer to the same value, nothing more. A short value such as a 6-digit code
could be guessed from its hash, but it stops working when the old PC finishes.

Limits:
  - The rewrite happens when the tool exits. If the window is killed or the PC loses
    power during a run, the log in the folder still holds the plain values. Delete it.
  - Only values the tool itself prints as secrets are hashed. Do not paste other
    sensitive data into the console during a run.
  - Saved Wi-Fi passwords are written to files in the export package, never printed, so
    they are not in the log.
